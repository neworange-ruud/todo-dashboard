# Buddy — session handoff

Created: 2026-10-06 09:56:58 CEST. This handoff is for an agent running on the target Mac. No Buddy implementation has been started.

## User's idea

The user wants to evolve the existing todo dashboard into a personal assistant called **Buddy** (working name), built as a **native macOS app**. It will occupy a separate, very small widescreen display positioned beneath the main monitor. Its face should fill that screen, with prominent eyes and thick Buddy Holly-style glasses. The eyes should follow the mouse cursor continuously, including when the cursor is on the main display above it.

Longer-term possibilities: low-friction, likely speech-to-text time logging for later entry into the company's hours system; spoken meeting-start notices; reminders about outstanding tasks; and notifications when a Fireflies transcript is processed. **The first implementation is only the cursor-following eyes.** The user asked for an assessment and questions to refine that first implementation, and requested the conversation continue in English.

## Assessment already given

Buddy has a distinct purpose as an always-visible presence rather than another dashboard view. The first prototype should be a face on the small display whose pupils track the cursor across all displays, without tying it yet to time tracking or other integrations. A native SwiftUI app with some AppKit for display and window handling is a reasonable candidate. The technical path is to get the macOS cursor position, map it relative to Buddy's display and eye positions, constrain pupil travel, and smooth the movement. Validate the actual behaviour and any OS permission requirements on the target Mac rather than assuming them.

## Questions asked; awaiting user answers

1. Small display resolution/orientation; is it connected to the same Mac and arranged directly below the main display in macOS settings?
2. Visual scope: oversized eyes and glasses on a background, or a fuller face with mouth and other features?
3. Eye behaviour: only pupils move within fixed eyes? Should they settle back to centre when the cursor stops or disappears?
4. Window behaviour: automatically placed borderless full-screen display, or manually positionable/resizable window during development?
5. Target Mac model and macOS version?
6. What would count as a successful first prototype? Proposed example: start Buddy, move the cursor anywhere across both displays, and have the eyes follow naturally without noticeable lag.

The user was also invited to share a photo or reference for the face/glasses style. Ask/collect these answers before choosing detailed UX and implementation parameters. Do not assume they have answered just because this handoff exists.
